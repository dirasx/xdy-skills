# Главный документ о правилах работы

При вызове `$xdy-docsproduct` прочитай целиком [assets/WORKFLOW.md](assets/WORKFLOW.md). Если пользователь просит только показать шаблон, выведи его одним блоком `markdown` и пропусти запись.

## Куда записывать

1. Найди целевой проект. Если пользователь или инструкции проекта указали закрытый рабочий репозиторий (например, Desk) и папку проекта в нём, используй эту связь. Для внутренних файлов проекта работай только с его папкой. Общий `WORKFLOW.md` находится в корне Desk. Отдельный `<проект>/WORKFLOW.md` нужен для правил конкретного проекта по прямому запросу или при переносе уже существующего документа.
2. Для связанного Desk создай общий `WORKFLOW.md` в его корне, если он отсутствует. Подтверди, что указанный каталог действительно является закрытым рабочим хранилищем. Если он недоступен, сообщи об этом и уточни путь. Не используй репозиторий приложения как запасное место.
3. Для самостоятельного проекта без связи с Desk запиши `WORKFLOW.md` в корень проекта, если репозиторий подтверждён как приватный, или в рабочий каталог, который пользователь явно указал как закрытый или локальный. Если репозиторий публичный или видимость удалённого репозитория неизвестна, уточни закрытое место. Запись публичных правил в публичный репозиторий допускается по прямому запросу пользователя.

## Запись и ответ

- Если целевого файла нет, скопируй шаблон дословно и сравни побайтово, например через `cmp`. Обычный вызов разрешает создание этого файла по правилам выше.
- Если файл уже совпадает, оставь его и сообщи об этом. Если в нём уже есть утверждённые правила, сохрани их и укажи путь. Заменяй существующий документ только по прямому запросу.
- Покажи полный шаблон дословно одним блоком `markdown` для копирования. После блока сообщи результат и путь, например «Добавил `WORKFLOW.md` дословно» только после подтверждённой записи. После записи или подтверждённого наличия правил закончи фразой «Принял правила из твоего скилла и готов работать по ним в этом проекте». При блокере укажи причину.
- Создание остальных документов, перенос старых файлов, коммиты и публикации выполняй только в рамках явно запрошенной задачи.
