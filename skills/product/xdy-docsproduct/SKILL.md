# Главный документ о правилах работы

Обычный вызов `$xdy-docsproduct` означает, что нужно создать `WORKFLOW.md` в проекте и показать полный шаблон. Вызов сам по себе даёт разрешение создать этот файл. Выполни запись до ответа, даже если пользователь ничего не добавил к команде.

1. Прочитай целиком [assets/WORKFLOW.md](assets/WORKFLOW.md) из каталога скилла. Найди корень целевого проекта: используй указанный пользователем каталог, а иначе корень активного Git-репозитория или открытый каталог проекта, если Git ещё не настроен. Если корень неоднозначен, уточни путь.
2. Если в корне нет `WORKFLOW.md`, скопируй шаблон в `WORKFLOW.md` без изменений. Не создавай файл в каталоге скилла или в произвольной подпапке. Сравни записанный файл с шаблоном побайтово, например через `cmp`.
3. Если `WORKFLOW.md` уже есть и совпадает с шаблоном, оставь его на месте и сообщи об этом. Если файл отличается, сохрани существующий документ и сообщи, что для замены нужна явная команда. При невозможности записи или сверки сообщи конкретную причину.

В ответе выведи полный шаблон дословно одним блоком `markdown` для копирования. Сохрани переносы строк и нейтральный заголовок «Как ведём проект». Сразу после блока отдельным абзацем сообщи результат. Только если новый файл действительно создан и совпадение проверено, напиши: «Добавил `WORKFLOW.md` дословно». После подтверждённой записи или совпадения существующего файла закончи фразой: «Принял правила из твоего скилла и готов работать по ним в этом проекте».

Если пользователь явно просит только показать шаблон, выведи блок без записи и без утверждения, что файл добавлен. Обычный вызов создаёт только корневой `WORKFLOW.md`. Остальные документы, коммиты и публикации требуют отдельной задачи.
